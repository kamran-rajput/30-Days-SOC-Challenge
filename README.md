## Project Overview

This repository documents my complete hands-on learning journey through a **30-Day SOC (Security Operations Center) Challenge**.

It is not a collection of copy-pasted study notes. It is a **practical portfolio** built to demonstrate real, applied understanding of SOC operations — the daily labs I ran, the commands I used, the concepts I broke down in my own words, and the investigation techniques I practiced along the way.

Every entry reflects independent, hands-on work completed after finishing each day's challenge, then rewritten and structured for clarity, revision, and public review.

The goal is simple: build a transparent, verifiable record of SOC-level skills that a recruiter, hiring manager, or fellow analyst can review in minutes.

---

## Learning Objectives

This challenge is structured around the core competencies expected of a Tier 1 / Tier 2 SOC Analyst:

- SOC fundamentals and analyst workflows
- Log analysis and correlation
- Threat detection techniques
- Incident investigation methodology
- Linux administration and command-line proficiency
- Windows administration and event log analysis
- Core networking concepts (TCP/IP, ICMP, HTTP, TLS)
- Packet analysis with Wireshark
- SIEM operations
- Wazuh deployment and use
- Splunk searching and dashboarding
- Email header and phishing analysis
- Threat intelligence fundamentals
- Detection engineering basics

## Study Methodology

<details>
<summary><strong>Click to expand: Daily Note Template</strong></summary>

Every day's notes follow a consistent structure, designed to reinforce both understanding and recall:

1. **Objective** — What the day's challenge is trying to teach.
2. **Concepts** — Core theory explained in my own words.
3. **Step-by-Step Labs** — The exact hands-on process I followed.
4. **Important Files** — Logs, configs, or artifacts referenced during the lab.
5. **Commands** — Every command used, with context on what it does.
6. **Gotchas** — Mistakes made, edge cases, and things that weren't obvious at first.
7. **Key Takeaways** — The 2–3 points worth remembering long-term.
8. **Summary** — A condensed version for quick revision later.

</details>

This structure exists for a practical reason: SOC work is repetitive and detail-heavy, and retention matters more than one-time exposure. Separating **raw learning** (Day files) from **condensed revision** (Summary files) means the notes double as both a learning log and a fast-reference cheat sheet — the same way an analyst would maintain a personal runbook on the job.
